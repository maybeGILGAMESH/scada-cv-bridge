# Эталонные образцы щита АСУ ТП для `cv2.matchTemplate`

Папка для распознавания панели `neft-hmi-cv.html` сопоставлением с эталонами.

## Как заполнить папку

Шаблоны нельзя подготовить заранее в стороннем редакторе: `matchTemplate` сравнивает
пиксели буквально, поэтому образец обязан быть вырезан из того же холста, что рисует
кадры. Нарезка делается один раз из самой панели:

1. Откройте `neft-hmi-cv.html`.
2. В группе **«Эталоны для matchTemplate»** выберите шаг стрелки (по умолчанию 5°).
3. Нажмите **«Выгрузить эталоны»** и укажите эту папку.

Chrome и Edge запишут файлы прямо сюда, папка запоминается — повторная выгрузка идёт
без диалога. Firefox и Safari не умеют писать в папку и отдадут `cv_templates.zip`,
его нужно распаковать сюда же.

Почему нельзя было положить готовые PNG в репозиторий: `matchTemplate` сравнивает
пиксели буквально. Образец, нарисованный любым другим кодом, отличался бы сглаживанием
и растеризацией шрифтов — совпадения не было бы. Единственный корректный источник —
тот самый холст, что рисует кадры, а он живёт в браузере.

После выгрузки появится:

```
manifest.json                  описание каждого образца
reference/frame.png            кадр, из которого нарезаны эталоны
reference/frame.json           истинные значения модели на этом кадре
validation/<компоновка>/       14 кадров разных режимов + JSON истинных значений
validation/index.json          список сценариев с указанием компоновки
templates/gauge/…              манометры: полный оборот стрелки с выбранным шагом
templates/sevenseg/…           знакоместа индикаторов: 0–9, точка, погашенное
templates/lamp/…               лампы: включена / выключена
templates/annunciator/…        окна щита тревог
templates/button/…             кнопки пульта: нажата / отпущена
templates/selector/…           поворотный переключатель режима: РУЧН / АВТО
templates/valve/…              арматура: открыта / прикрыта / закрыта
templates/pump/…               насосы: работа / стоп
templates/apparatus/…          блочные аппараты
templates/bargraph/…           столбчатые индикаторы: пустой и полный
templates/vessel_level/…       аппараты с уровнем: пустой и полный
templates/trend/…              тренды с пустой историей
templates/status_text/…        строка состояния объекта
templates/text_readout/…       текстовые табло
masks/…                        13 масок: 6 циферблатов, 5 задвижек, 2 насоса
```

При шаге 5° это 527 образцов; шаг 2° даёт 836, шаг 10° — 365.
Всего щит содержит 82 размеченных объекта, из них 13 — органы управления
(кнопки пуска и останова, «больше/меньше» для задания ЧРП и штуцера,
переключатель режима регулятора, ингибитор, промывка, АПВ, ТКРС).

## Как проверить

```bash
pip install opencv-python numpy

python match_templates.py                                  # весь контрольный набор
python match_templates.py --reference                      # только исходный кадр
python match_templates.py --frame кадр.png --truth кадр.json
python match_templates.py --dataset ../scada_cv_dataset --limit 50
python match_templates.py --only gauge,sevenseg_digit
python match_templates.py --save-overlay overlay.png
python match_templates.py --anchored                       # старый режим: по якорям
```

Скрипт печатает таблицу «распознано / эталон / балл / отрыв» и сводную точность по
классам. Колонка «отрыв» — разрыв между лучшим и вторым шаблоном: это и есть мера
достоверности. Балл 1.000 при нулевом отрыве означает, что прибор чем-то перекрыт и
сравнение бессмысленно.

### Почему проверка идёт по набору, а не по одному кадру

Сверять распознавание на `reference/frame.png` — слабая проверка: именно из этого кадра
нарезаны эталоны, и совпадение там гарантировано устройством дела. Поэтому выгрузка
кладёт ещё и папку `validation/` — 14 кадров, снятых в заведомо разных режимах:

| сценарий | чем интересен |
|---|---|
| нормальный режим 50 Гц | равновесие после прогона физики |
| останов, уровень восстановлен | насос стоит, столб жидкости поднялся |
| авария по перегреву ПЭД | мигающие тревоги, красная строка состояния |
| срыв подачи, ожидание АПВ | предельно низкое погружение |
| автомат на высокой частоте | регулятор ведёт частоту сам |
| штуцер прижат до 25 % | высокое буферное давление |
| высокая обводнённость | 92 % воды |
| парк полный, откачка в работе | резервуары под 93 %, насосы крутятся |
| парк почти пуст | 6 % и 9 % |
| сепаратор на верхнем уровне | 93 %, сработал ППК |
| низкая изоляция | предупреждение без отключения |
| нижний край шкал | все стрелки на нуле |
| верхний край шкал | все стрелки у верхнего предела |
| кольматация ПЗП и АСПО | падение дебита, рост вибрации |

Крайние точки шкал важны отдельно: именно на них вылезают ошибки экстраполяции угла и
насыщение измерения уровня.

Что с чем сверяется: PNG — обычный растр 1920×1080 без метаданных, распознавание видит
только его. JSON — истинное состояние модели в момент отрисовки этого же кадра: значение
каждого прибора, угол стрелки, текст табло, процент уровня. Это не журнал событий, а
числа, из которых пиксели и были нарисованы.

## Компоновки щита и почему это не чтение по координатам

Справедливый упрёк к первой версии: образцы резались из того же кадра, что и
проверялся, а поиск шёл в окрестности `anchor ± pad`. Приборы стояли на
известных местах, и по одному только отчёту нельзя было отличить настоящее
распознавание от чтения заранее известной точки.

Поэтому у щита теперь четыре компоновки. Они переставляют блоки целиком, не
меняя ни размера прибора, ни его отрисовки — меняются только координаты:

| компоновка | что переставлено |
|---|---|
| A · базовая | мнемосхема слева, приборы в центре, сигнализация справа |
| B · зеркальная | колонки обеих полос в обратном порядке |
| C · приборы слева | манометры и индикаторы к левому краю, мнемосхема в центре |
| D · полосы наоборот | нижняя полоса поднята под шапку, верхняя опущена вниз |

Переключаются в панели списком «Компоновка щита» или клавишей <kbd>L</kbd>.

Скрипт сверки больше не верит координатам. Перед чтением приборов он **находит
блоки щита в кадре**: из контрольного кадра вырезается кусок блока целиком и
ищется во всём кадре — грубо на уменьшенной вчетверо паре, затем с уточнением
на полном разрешении. Дальше якорь каждого прибора сдвигается на найденную
величину, и чтение идёт как прежде. Так работает режим по умолчанию; старое
поведение осталось под ключом `--anchored`.

Блоков восемь, приборов в них 81 из 83. Оставшиеся два — часы и строка
состояния объекта — живут в шапке щита, а шапка не переставляется ни в одной
компоновке, поэтому им сдвиг не нужен. Заодно шапка служит опорой при чтении с
видеотрансляции: по её неизменной части ищется масштаб кадра.

Разница на одном и том же кадре, эталоны нарезаны в компоновке A:

| кадр | по якорям (`--anchored`) | с поиском блоков (по умолчанию) |
|---|---:|---:|
| компоновка A | 67 / 67 — 100 % | 67 / 67 — 100 % |
| компоновка B | 33 / 67 — 49,3 % | 67 / 67 — 100 % |
| компоновка C | — | 67 / 67 — 100 % |
| компоновка D | 27 / 67 — 40,3 % | 67 / 67 — 100 % |

Сорок процентов в режиме по якорям — это не остатки распознавания, а цена
угадывания: у двухпозиционных приборов одно из состояний совпадает случайно.
Существенно тут другое: перестановка блоков валит чтение по координатам и
никак не задевает чтение по изображению.

Заодно исчезла ещё одна незаметная подсказка. Знакоместа семисегментных
индикаторов раньше брались из JSON проверяемого кадра — то есть из истины,
которую полагается только сверять. Теперь они берутся из разметки контрольного
кадра и сдвигаются туда, где нашёлся блок; истинная разметка кадра нужна
исключительно для сверки результата.

### Отпечаток компоновки

`layout_signature` по-прежнему считается, но сменил роль. Раньше расхождение
отпечатка означало «эталоны устарели, перевыгрузите». Теперь оно означает
всего лишь другую компоновку — и это штатный случай. Предупреждение осталось
только в режиме `--anchored`, где расхождение действительно ломает чтение.

## Что важно знать про matchTemplate

**Масштаб и поворот не прощаются.** Метод сравнивает прямоугольник пикселей как есть.
Для сверки берите кадры, выгруженные **без аугментаций** (галочка «аугментации» в
панели), либо с одними фотометрическими искажениями. Поворот даже на 2° роняет балл
примерно вдвое. Если нужна устойчивость к повороту — это уже задача для
`cv2.matchShapes`, дескрипторов ORB/SIFT или обучаемого детектора.

**Яркость и шум не мешают.** `TM_CCOEFF_NORMED` вычитает среднее и нормирует
дисперсию, поэтому изменение яркости на ±25 %, контраста на ±15 %, шум и сжатие JPEG
до 60 % балл почти не двигают.

**Эталоны стареют.** Любая правка щита сдвигает приборы, и старые образцы начинают
тихо ронять точность вместо явной ошибки. Поэтому в `manifest.json` и в аннотацию
каждого кадра пишется `layout_signature` — отпечаток типов, идентификаторов и габаритов
всех приборов. Скрипт сверяет их и предупреждает о расхождении. Отпечаток не зависит от
показаний, только от компоновки.

**Поиск ограничен окрестностью — но окрестность вычисляется, а не задана.** В
`manifest.json` у каждого образца есть `anchor` (левый верхний угол в контрольном
кадре) и `block` (в каком блоке щита он находится). Сначала в кадре ищется сам
блок, затем якорь сдвигается на найденную величину, и прибор ищется в окрестности
`±--pad` (по умолчанию 36 px) уже от сдвинутого якоря. Полный проход по кадру для
каждого из 527 образцов был бы на порядок дороже и давал бы ложные срабатывания
на похожих приборах; поиск блока — один на восемь десятков приборов.

## Как читаются показания

| Прибор | Приём |
|---|---|
| Манометр | перебор образцов по углу, максимум балла, затем параболическое уточнение по трём соседним углам. Погрешность при шаге 5° — доли процента шкалы |
| Семисегментный индикатор | каждое знакоместо сравнивается с 11 образцами своего индикатора; координаты знакомест берутся из `reference/frame.json` |
| Столбчатый индикатор | корпус ищется по маске неизменной части, длина заливки — по отличию от эталона «пусто», от левого края |
| Аппарат с уровнем | так же, но ищется верхняя граница непрерывного столба жидкости от дна |
| Лампы, тревоги, кнопки, переключатели, арматура, насосы | выбирается состояние, набравшее больший балл |

### Почему у столбчатых нет файла маски

В `masks/` лежат только те маски, что нельзя вывести из данных: круги циферблатов и
контуры арматуры с насосами. Для столбчатых и уровневых маска **считается на лету** —
как пиксели, **совпадающие** у образцов «пусто» и «полно». Это ровно неизменная часть
корпуса: подпись, единицы, рамка. По ней прибор находится точно, тогда как поиск по
одному из состояний сдвигал рамку на 10–20 px и ломал измерение.

### Как из столбчатого получается число

Три шага, все параметры берутся из пары эталонов, руками ничего подбирать не нужно.

1. **Положение.** Поиск с маской неизменной части (`TM_SQDIFF` с `mask`).
2. **Дорожка шкалы.** Её прямоугольник лежит в манифесте — `fill_rect_rel` у образца
   «полный», в координатах шаблона. У аппаратов с уровнем это `liquid_rect_rel`.
3. **Длина заливки.** Для каждого столбца считается отличие от эталона «пусто»
   (75-й процентиль модуля разности по пикселям). Заполненная часть — непрерывный
   участок отличий, примыкающий к левому краю; у аппаратов — ко дну. Порог берётся
   как треть от того отличия, что дают между собой сами эталоны «пусто» и «полно».

Мерить по абсолютной яркости было бы неверно: цвет заливки меняется по тревоге, красная
полоса темнее синей, и порог, откалиброванный по синему эталону, давал бы ноль на
красной. Отличие от пустой шкалы срабатывает при любом цвете.

Отдельно учтено, что «пусто» не всегда пусто: у аппарата на дне остаётся неснижаемый
остаток, и там оба эталона выглядят одинаково. Такие полосы исключены из измерения, но
засчитаны в заполненную часть — иначе отсчёт от дна обрывался бы сразу и уровень читался
бы как ноль.

Погрешность на прогоне по всему диапазону: **0,2 % шкалы** у столбчатых и **0,7 %** у
уровня, включая кадры, где цвет заливки не совпадал с цветом эталона.

## Что показал первый прогон на настоящем щите

93,8 % с ходу: манометры, лампы, тревоги, кнопки, арматура, насосы, блочные аппараты и
столбчатые — всё по 100 %. Четыре расхождения оказались настоящими дефектами, все
устранены.

**Панель журнала событий рисовалась поверх двух нижних индикаторов.** `TM_CCOEFF_NORMED`
вырождался и возвращал 1.000 сразу всем одиннадцати шаблонам цифр — балл идеальный,
информации ноль. Журнал переехал в отдельную полосу под трендами.

Заодно выяснилось, что признаком такой беды служит не сам балл и не однородность
участка (там был разброс яркости 6, а не ноль), а **отрыв лидера от второго места**.
Скрипт теперь считает этот отрыв: при нулевом отрыве знакоместо читается как `?`,
строка помечается «НЕДОСТОВЕРНО», а не выдаётся за уверенный ответ. Отрыв виден
отдельной колонкой в таблице — у нормально читаемых индикаторов он 0,13–0,21.

**Табло объёма внутри резервуара лежало на столбе жидкости.** Оно закрывало полосу
шкалы, и уровень читался как 79 % вместо 59 %. Табло вынесено на юбку под обечайкой;
внутри остались только жидкость, волна и поплавок на тросе.

**Прямоугольник уровня снят при 95 %, а не при 100 %** — иначе граница жидкости слилась
бы с кромкой аппарата. Шкала теперь растягивается обратно по `level_pct` эталона.

**Врезки давлений у скважины разрывали столб жидкости.** Скрипт научился проходить
сквозь незначимые полосы, а не останавливаться на них.

## Проверка методики

Конвейер проверен на синтетическом стенде той же структуры: два манометра со стрелками
в положениях **между** узлами сетки образцов, пятиразрядный индикатор, лампа, арматура,
столбчатый индикатор и аппарат с уровнем.

| Прибор | Истина | Распознано |
|---|---|---|
| Манометр A | 37,00 | 37,03 |
| Манометр B | 162,40 | 162,69 |
| Индикатор | 04217 | 04217 |
| Столбчатый | 94,50 | 94,64 |
| Уровень | 42,00 % | 42,61 % |

100 % совпадений, в том числе на кадрах с яркостью 0,8–1,25, контрастом 0,9–1,15,
гауссовым шумом σ до 18 и JPEG качества 64.
