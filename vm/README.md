# Стенд на виртуальной машине: щит в ВМ, «HDMI» снаружи, дашборд зрения

Щит работает не в браузере на том же компьютере, а в отдельной ВМ — как на
настоящем АРМ, к которому подключён KVM. Экран ВМ снимается снаружи, как карта
захвата снимает HDMI, и отдаётся MJPEG-потоком в формате PiKVM; мышь и
клавиатура уходят в ВМ как USB HID. Поэтому `live/run.py` и
`bridge/receiver.py` работают с ВМ без изменений, а когда появится настоящий
HDMI-захват, меняется только адрес потока.

```
ВМ (Debian 13, Chromium в киоске, щит 1920×1080)
   │ экран — VNC 127.0.0.1:5900                ▲ мышь/клавиатура — VNC
   ▼                                           │
vm/vmhdmi.py ── MJPEG :8781 /stream ──▶ receiver.py · live/run.py · vm/cvdash.py · vm/vmview.py
             ◀─ обратный канал :8790 (JSON-строки, как у bridge/emulator.py) ─┘
```

ВМ работает в фоне без окна — компьютер остаётся свободным. Окно с экраном ВМ
открывается по желанию (`vmview.sh`, F11 — на весь экран), его и можно вывести
на HDMI.

## Запуск

Нужны Linux с KVM, Python 3.10+, Chrome/Chromium не нужен (браузер — внутри ВМ).

```bash
sudo apt install -y qemu-system-x86 qemu-utils cloud-image-utils tesseract-ocr
python3 -m venv .venv && .venv/bin/pip install -r vm/requirements.txt
vm/setup-vm.sh            # скачает образ Debian 13, соберёт диск ВМ и cloud-init
vm/fetch_tessdata.sh      # русская модель Tesseract для журнала (в vm/tessdata/)
./start.sh                # ВМ в фоне + vmhdmi; первый запуск ВМ — 3–5 мин
./cvdash.sh               # дашборд зрения http://localhost:8775/
./stop.sh                 # всё выключить
```

| скрипт | что делает |
|---|---|
| `start.sh` / `stop.sh` | ВМ в фоне + `vmhdmi`; остановка всего, включая дашборд |
| `vmview.sh` | окно с экраном ВМ, мышь и клавиши уходят в ВМ; F11 — полный экран, Esc — выйти из него |
| `cvdash.sh` | дашборд «что видит система» |
| `run-hdmi.sh` | щит без ВМ: Chrome в киоске на этом же компьютере |
| `vm/run-vm.sh` | `--window` — ВМ с окном QEMU; `stop`, `status` |
| `vm/vmcheck.py` | `speed` · `accuracy` · `e2e` · `all` — замеры, отчёты в `vm/results/` |

В ВМ: `ssh -i vm/ssh_key -p 2222 scada@127.0.0.1` (ключ создаёт `setup-vm.sh`).
На щите: **H** — панель управления (частота, штуцер, отказы, компоновки),
**L** — компоновка, **B** — разметка, **Esc** / кнопка «Закрыть» — выход в
консоль ВМ (`startx` — обратно).

## Скорость «HDMI»-канала ВМ

`vm/vmcheck.py speed`, QEMU/KVM 4 vCPU, кадр 1920×1080, JPEG q80:

| метрика | значение |
|---|---:|
| поток MJPEG у клиента | 30 к/с, интервал 33 мс (p95 35, макс 42) |
| кадр · поток | 293 КБ · 69 Мбит/с |
| от кодирования до клиента | 10 мс (p95 12) |
| клавиша → изменение в потоке | 78 мс (p95 82) |
| клик мышью → изменение в потоке | 113 мс (p95 146), из них 50 мс — удержание кнопки |
| потеряно команд ввода | 0 из 40 |
| CPU хоста: QEMU / vmhdmi | 1,2 ядра / 0,3 ядра |

Сквозной контур (`vm/vmcheck.py e2e`): штатный `receiver.py` на потоке ВМ сам
жмёт кнопки щита в ВМ по картинке — пуск, останов, частота 45 Гц, штуцер 60 %,
пуск/останов в компоновках B, C, D — **12/12**. Ключ `--no-normalize` здесь
обязателен по смыслу: кадр ВМ уже 1:1, а без него калибровка по шапке (эталоны
сняты в Windows, шрифты другие) находит масштаб 1,012 и читает втрое медленнее.

## Дашборд «что видит система»

`vm/cvdash.py` читает тот же поток тем же `FastReader`, что и `receiver.py`,
и показывает:

* кадр с наложением: блоки, найденные `matchTemplate` (балл, сдвиг), рамки
  приборов с цветом сверки, найденные стрелки манометров, оцифрованные кривые
  трендов, вырезанные значения табло;
* по щелчку — шаги OpenCV для прибора: развёртка `cv2.remap` и профиль
  «красноты» стрелки, знакоместа индикатора против всех цифр, сравнение
  состояний лампы, профиль заливки шкалы, карта корреляции блока; для табло —
  символы против глифов, для трендов — точки линий и клон, для журнала — вход
  и выход OCR;
* точность по классам, время по этапам, гистограмма ошибки манометров, клон
  трендов, журнал щита против журнала модели, историю за 3 минуты;
* управление щитом и «Точная проверка» — модель на паузе, кадр и истина
  одного момента.

Истина модели берётся из страницы щита через DevTools по ssh-туннелю — только
для оценки, распознавание её не видит.

Скриншоты — `vm/results/screens/`.

## Что читается сверх FastReader

FastReader у текстовых табло и трендов только находит место, а журнал не
трогает. `vm/extra_reader.py` дочитывает:

| объект | как | результат |
|---|---|---|
| 11 табло (задания ЧРП и штуцера, давления у скважины, сепаратор) | значение — по насыщенному цвету, цифры — глифами моноширинного шрифта | 660/660 вживую |
| часы модели | глифы | 60/60 |
| журнал, 2 строки | время — глифы, источник — эталоны всех 14 источников щита, сообщение — Tesseract (rus+eng) | 60/60 |
| 3 тренда | шкала — подписи оси глифами; кривая — точки по яркости, серия по оттенку | СКО кривой 0,2–0,36 % шкалы, последнее значение — до 0,5 % |

**Точная проверка: 82/82 объекта в каждой из четырёх компоновок A–D.**
Вживую (насос в работе, модель ×30) — 99,84 % при ~10 к/с.

## Что нашлось по дороге

* **Эталоны в `cv_templates/` нарезаны со старой версии щита.** Три табло у
  скважины (PT-104, PT-105, Р пластовое) с тех пор переехали и стали 62×44
  вместо 126×31: эталон находил мусор с баллом 0,1, рамка прыгала по кадру.
  `vm/regen_templates.py` перенарезает весь банк кнопкой щита «Выгрузить
  эталоны» прямо в ВМ (через DevTools) в `vm/cv_templates_vm/` — исходный банк
  не трогается. Дашборд работает с новым банком.
* **Ошибка выгрузки щита у КУ-1:** `measure_span_pct` = 100 при эталоне
  «полно» на 84 % — уровень завышался в 1,19 раза. Поправка — в
  `regen_templates.fix_manifest`.
* **Кэш FastReader держит устаревшие цифры индикаторов.** Смена одной цифры
  меняет отпечаток области меньше порога `change_thr=1.2`: вживую индикаторы
  71 % с кэшем против 97,5 % без него. Код FastReader не менялся.
* **Ноль DejaVu Sans Mono — с точкой внутри**, Tesseract читает его как 8, 9
  или 6. Отсюда чтение цифр глифами: `vm/glyph_ocr.py` нарезает их
  автоматически из контрольных кадров (и их JPEG-версий), `vm/glyph_live.py`
  добирает недостающие с живого щита. Сверка — 3075/3078 надписей.
* **MJPEG хранит цвет вдвое грубее (4:2:0)**: тонкая линия тренда теряет свой
  цвет, поиск по точному цвету находил 1 % кривой. Точки отбираются по
  яркости, серия — по оттенку сглаженного цвета. Настоящая карта захвата даст
  то же самое.
* Латиница и кириллица одинакового начертания (C/С, A/А, B/В) по картинке не
  различимы — сверка журнала сводит их к одному виду, читаемое не меняется.

## Несколько систем, плейбуки, самовосстановление

Систем под наблюдением несколько — реестр `vm/systems.json`, поднимает
`vm/fleet.py` (`./start.sh` — все сразу). На стенде четыре ВМ:

| система | щит | что на ней видно |
|---|---|---|
| `well1247` | основной АРМ, компоновка A | основная ВМ (4 vCPU, 4 ГБ) |
| `well1248` | тот же щит, компоновка C, износ (АСПО), ×120 | технологический плейбук «Отложения АСПО» |
| `well1249` | тот же щит, компоновка D | перестановка блоков, плейбук нормы |
| `newsys` | **другой щит** (`neft-scada.html`), профиля нет | подготовка новой системы |

Дашборд (`./cvdash.sh`) — четыре вкладки:

* **Обзор систем** — живые миниатюры, статус (норма / внимание / авария /
  распознавание / нет сигнала / подготовка), точность, замечания;
* **Зрение** — то, что было: кадр с наложением и шаги OpenCV; для системы без
  профиля — автопоиск областей, надписи (Tesseract), сравнение с известными
  профилями и чек-лист готовности;
* **Плейбуки** — что делать, собирается из распознанного на экране этой
  системы (`vm/playbooks.py`). Шаг с органом управления, которого нет на этом
  щите, помечается недоступным. Виды шагов: ⚡ нажатие на щите через HID с
  проверкой результата по картинке (с подтверждением оператора), 🛠 исправление
  распознавания или инфраструктуры, 👁 проверка на экране;
* **На чём работает** — конвейер выбранной системы и хост, ВМ, гостевая ОС,
  захват, распознавание, профиль, порты (`vm/infra.py`).

**«Системы» и «Зрение» — две стороны.** «Системы» — сам щит, как у оператора:
живое видео экрана ВМ (MJPEG через дашборд, `/stream`), щелчки, перетаскивание
(ползунки), колесо и клавиши уходят в него (`POST /api/hid`, тот же HID-канал
`vmhdmi`, что у шагов плейбуков); тестовый канал стенда — тоже здесь. «Зрение» —
KVM: получает только видео и распознаёт, нажимать в нём нечего (рамки на кадре
показывают шаги OpenCV). «Рядом зрение» на «Системах» — справа кадр зрения,
точность, задержка и **реакция на нажатия**: после каждого щелчка — какие
объекты зрение увидело изменившимися, через сколько и сходится ли со щитом
(например, «ПУСК» → нажата, «НАСОС В РАБОТЕ» → вкл через 0,9 с ✓), медиана
реакции. «Щит в окне» (`/system?sys=<id>`) и «Зрение в окне»
(`/?tab=vision&sys=<id>`) — то же отдельными окнами, их можно поставить рядом;
система, которую смотрят, читается на полной скорости. Каждое действие
оператора — в журнале на «Плейбуках».

Проверено `vm/clickcheck.py`: каждая кнопка каждого щита — настоящим щелчком в
браузере там, где она видна, в окне и на вкладке, при окнах 1100×900 …
1920×1080; щит в ВМ на время проверки только записывает попадание (сам щелчок
не проходит, «АВАР. СТОП» не срабатывает). Отчёт — `vm/results/clickcheck.md`.
Найдено и исправлено: в «Щите в окне» картинка растягивалась (высота окна
ограничивала рамку 16:9), а пересчёт щелчка считал её вписанной — правые
кнопки уезжали (161 из 248 попаданий); теперь картинка вписывается без
растяжения — 244 из 244. Ползунки уставок старого щита через VNC не тянулись:
абсолютную мышь QEMU (USB-планшет и vmmouse) Chrome в X11 считает пером, а пером
`<input type=range>` не перетаскивается. Перетаскивание оператора теперь идёт
обычной мышью X в госте (`xdotool` по постоянному ssh-каналу,
`fleet.GuestPointer`); щелчки, клавиши и нажатия плейбуков — по-прежнему HID
через VNC, как у KVM.

Список систем слева сворачивается кнопкой-стрелкой над ним (или клавишей `[`) в
узкую полосу: короткая метка (`short` в `systems.json`), цвет статуса и
точность — переключать системы можно и так, а кадру «Зрения» достаётся больше
места. Выбранная система тогда видна в верхней полосе, щелчок по ней
разворачивает список. Состояние запоминается в браузере.

**Самовосстановление** (по умолчанию включено): исправления распознавания и
инфраструктуры выполняются сами, не чаще раза в минуту на действие. Нажатия
на щите — только по кнопке оператора. Проверено на стенде:

* щит в аварии (ЗСП по изоляции 5 кОм) — плейбук «ТКРС → КВИТ → ПУСК»,
  каждое нажатие подтверждено на экране (изоляция 240 кОм, «ЗСП ОТКЛЮЧЕНИЕ»
  погасло, «НАСОС В РАБОТЕ» горит);
* окно поверх щита — через 3 с «часть щита закрыта» (объекты под ним не
  считаются ошибками), Esc через HID, через 6 с щит снова виден;
* щит в ВМ закрылся — «щит не виден», перезапуск щита в ВМ по ssh;
* устаревшие цифры индикаторов из кэша — кэш для индикаторов отключается сам.

Устойчивость к виду системы:

* блоки с повторяющимся узором (шесть одинаковых шкал, сетка табло)
  привязываются по заголовку — сопоставление блока целиком съезжало на шаг
  узора, и «КПД» читал число «Погружения»;
* шкалы читаются по числу справа (видно и за пределом шкалы), ствол — по
  риске «Ндин» (подпись рядом отличает её от стрелок притока);
* табло тревоги мигают — для плейбуков «горит» = горело за последние ~10 кадров;
* серия тренда, лежащая под другой, — «скрыта», а не ошибка;
* недостающие состояния дискретных объектов (у фонтанной арматуры выгрузка
  щита режет только «работает») добираются из контрольных кадров;
* Esc больше не закрывает щит (выход — кнопка «Закрыть» или Ctrl+Shift+Q):
  Esc закрывает всплывающие окна, в том числе самовосстановлением.

Точная проверка (модель на паузе) — 89 объектов на систему, включая табло,
шкалы, ствол, тренды, журнал и часы: 89/89 на компоновках C и D.

## Новая система: профиль со страницы щита

Четвёртая система — старый щит `neft-scada.html`: своей CV-разметки и
«Выгрузить эталоны» у него нет. Профиль распознавания снимается со страницы
(`vm/dom_profile.py`, в дашборде — шаг плейбука подготовки «Собрать профиль»):

* через DevTools берутся места элементов: 24 табло, значки состояния
  оборудования, плашка в шапке, часы, кнопки, журнал, подписи мнемосхемы,
  заголовки панелей (опоры привязки);
* щит прогоняется через 17 состояний (пуск, аварии по изоляции и перегреву,
  ожидание АПВ, аварийный останов, предупреждения, ремонт, переключатели),
  кадр каждого — без потерь и JPEG;
* из них — глифы (4 варианта банка: склейка разрыва 1/2 px × порог 0,35/0,55
  против ореола светящихся цифр), цветные эталоны фраз, состояния кнопок,
  цвета рамок уровня табло;
* **прогон цифр**: в 17 состояниях встречаются не все цифры (засорение НКТ
  всегда около 1.00), и банк о недостающих гадал — «4.61» читалось «4н01»,
  «895» — «695». Поэтому после состояний отрисовка щита на паузе замораживается,
  и в каждое из 43 числовых полей 10 раз подставляется текст того же вида, где
  цифра на позиции j — (k + j) mod 10: каждая позиция проходит все цифры;
* **самопроверка** на тех же кадрах выбирает для каждого объекта лучший банк, а
  для чисел — и способ: глифы или Tesseract по увеличенной области ×3/×4 (мелкий
  SVG-текст 10 px и значки 15 px, где буквы «сут», «Ндин», «.»/«:» глифами не
  набираются). Tesseract вызывается только при изменении текста (кэш по
  двоичной картинке надписи); плавающая подпись, слипшаяся с соседями («14:08 ·
  сут 46», «Ндин» у линии уровня), читается по ключевому слову — не чаще раза в
  секунду. Объекты хуже 80 % — «ненадёжно»: показываются «не уверено», плейбуки их
  чтения не используют. Сейчас надёжно 75 из 75 (на 27 кадрах с прогоном цифр;
  глифы — 30 чисел, Tesseract — 11).
* **свой банк поля**: общий банк смешивает шрифты — «0» с точкой внутри у
  мнемосхемы (10 px) после JPEG ближе к «9» другого шрифта, и «Р буф 12.0»
  читалось «12.9» обоими способами. Для каждого числового поля строится банк
  только из его образцов (прогон цифр даёт все цифры), точность — на
  отложенных кадрах; выбран для 23 полей из 41. Tesseract дополнительно
  сверяется с глифами: разошлись в числах — «не уверено». «Точная проверка»
  (модель на паузе) — 100 % (94/94); вживую на ×30 расхождения — только в
  меняющихся значениях между кадром и истиной (засчитывается истина до и после
  кадра).

Распознаёт `vm/generic_vision.py` (тот же контракт, что основной распознаватель);
плейбуки для этого щита — своя библиотека (`legacy_library`): причина аварии
со значка «Защита ЗСП», шаги — «ТКРС — устранить все», «Сброс защит», «Пуск»,
«Промывка», «Ингибитор», «Авторегул. уровня».

Вживую: значки, плашка, кнопки, уровни табло, журнал — 100 %, всего 99,3–100 %.
Чтение цифры с почти нулевым отрывом от соседнего глифа помечается «не уверено»
(так же — на табло первого щита).

Найдено по дороге: окно переводчика Chromium висело поверх щита во время
первой калибровки и попало в эталоны плашки. Переводчик теперь выключен
политикой Chromium в ВМ (`TranslateEnabled: false`, есть в cloud-init), а
калибровка перед съёмкой закрывает всплывающие окна (Esc).

## Проверка плейбуков

`python vm/pbcheck.py [--sys newsys] [--scen stopped,trip,asp]` — на живых
системах тем же путём, что кнопки дашборда: тестовым каналом создаётся ситуация
(насос остановлен / пробой изоляции / отложения АСПО), система сама видит её на
экране и собирает плейбук, шаги идут через `/api/fix` (HID по месту на кадре,
подтверждение по картинке), итог сверяется с истиной модели. Отчёт —
`vm/results/pbcheck.md`. Последний прогон: 12 сценариев на 4 системах — все шаги
подтверждены по картинке и по истине; на АРМ-2 (×120, износ насоса) модель после
пуска сама отключается по недогрузу и ждёт АПВ — это поведение щита, его теперь
ведёт плейбук «ожидание АПВ».

Что этим нашлось и исправлено:

* **«Пуск» на основной ВМ не срабатывал.** Ядро гостя усыпляет USB-планшет QEMU
  (autosuspend); у основной ВМ мышь шла именно в него, и первое событие после
  простоя (переход к кнопке) терялось — нажатие приходило в старую точку
  курсора. Плейбук честно писал «не подтвердилось». Теперь: правило udev не
  усыпляет USB-ввод QEMU (`/etc/udev/rules.d/90-qemu-input-awake.rules`, есть в
  cloud-init, применено во всех ВМ), а `vmhdmi` перед нажатием подводит курсор
  двумя движениями.
* **После перезапуска `vmhdmi` нажатия с дашборда молча не работали** (в том
  числе после самовосстановления «перезапустить HDMI-службу»): обратный канал
  держал закрытое соединение. Теперь пустой ответ — переподключение.
* **Насос остановлен, но «Пуска» нет**, если горит любое предупреждение (АСПО,
  вибрация): «Насос остановлен» собирался только при отсутствии других
  замечаний. Теперь — всегда, когда насос стоит без защиты и пуска нет в другом
  плейбуке.
* **«Ингибитор» — переключатель**: повторный прогон плейбука выключал уже
  включённый дозатор. Теперь, если он горит, шаг — проверка, а не нажатие.
* **На старом щите не было плейбука АСПО**: засорение видно только по значку
  «Коэф. засорения НКТ» (рамки табло нормальные) — добавлен.
* **Ожидание АПВ на первом щите принималось за «Насос остановлен»** и
  предлагался ручной «ПУСК». Теперь по шапке «ОЖИДАНИЕ АПВ» / мигающей лампе
  «АПВ ГОТОВ» — плейбук «Отключение по недогрузу / срыву подачи»: без ручного
  пуска, регулятор уровня в АВТО (если выключен), причина — из журнала.
  Неподтверждённый шаг теперь пишет, что щит показывает вместо ожидаемого.
* **Плейбуки не строятся на догадках**: чтение «не уверено» для них — как не
  прочитано, шаг им не подтверждается.
* **Тестовый канал на старом щите** («Ремонт», «ЧРП ±») падал молча — у щита
  `repair()`/`sync()` вместо `cmdRepair()`/`syncUI()`; теперь работает на обоих,
  ошибки показываются под кадром, «Компоновка» скрыта, где компоновок нет.

## Автоматический режим: жизнеспособность и работоспособность

На «Плейбуках» у каждой системы — «Режим работы»: **Ручной** (как раньше —
нажатия на щите только по кнопке оператора) или **Автомат** (`vm/autopilot.py`,
режим запоминается в `vm/autopilot.json`).

**Жизнеспособность** — сквозная проверка цепочки, на которой держится зрение:
ВМ запущена → гостевая ОС отвечает → щит открыт → видео («HDMI») идёт → кадры
свежие → зрение читает → точность ≥ 95 % → щит виден целиком → HID-канал
отвечает → канал сверки → последнее нажатие подтверждено. У каждой проверки —
ремонт (запустить ВМ, перезапустить щит, «HDMI»-службу, сбросить кэш, Esc,
переподключить сверку). «Проверить сейчас» / «Проверить и починить» — в любом
режиме; в автомате — сама раз в минуту, чинит по одному за раз (не чаще раза в
2 мин на проверку).

**Работоспособность** — в автомате система сама выполняет технологические
плейбуки (авария → ремонт, сброс, пуск; насос стоит → пуск; отложения →
промывка, ингибитор; ожидание АПВ → регулятор уровня), самые серьёзные первыми:

* каждый шаг-действие — нажатие на щите через HID с подтверждением по картинке;
* шаг не подтвердился — плейбук остановлен и отложен на 5 мин;
* две неудачи одного плейбука за 30 мин — **«нужен оператор»**: автомат этот
  плейбук больше не трогает, пока оператор не снимет эскалацию (значок на
  «Обзоре» и в списке систем);
* после успешного плейбука — пауза 3 мин на него, щит приходит в новое состояние;
* пока цепочка сломана (нет ВМ, видео, HID, щит закрыт), технологию не трогает —
  результата не было бы видно; сначала ремонт цепочки.

Переключатели («Ингибитор», «Авторегул. уровня», «РЕЖИМ ЧРП») нажимаются только
если выключены — иначе повторное выполнение плейбука выключило бы их.

Проверено вживую: К-14 — пробой изоляции, автомат сам: ремонт → сброс защит →
пуск, 26 с; АРМ-3 — насос остановлен → пуск за 1 с; «HDMI»-служба убита →
перезапущена самовосстановлением за 6 с; щит перестал принимать щелчки → две
неудачи «Пуска» → «нужен оператор»; эскалация снята → пуск через 6 с.

## Случайная SCADA: распознавание без профиля

Пятая система — генератор случайных щитов `random-scada.html` (в общей папке
со щитами, ВМ `vm5`). Каждое зерно — другая станция: название, тема (тёмные и
светлые), шрифт (7 начертаний DejaVu/Liberation), сетка панелей, набор
приборов — числовые табло (подпись сверху или слева), стрелочные приборы со
своей шкалой (диапазон, сектор 180–300°, цифровое табло или нет), шкалы-полосы,
резервуары, лампы, кнопки-переключатели (нажимаются), тренды, журнал. Значения
живут. «Новая случайная станция» — на тестовом канале («Системы»).

Распознаёт `vm/zero_vision.py` — без профиля, эталонов и DevTools, только
по пикселям и общему знанию, как выглядит SCADA:

* строки текста — морфологический градиент, куски одной строки склеиваются
  (точка в крупном шрифте разрывает «147.56»), Tesseract по каждой строке со
  своей полярностью; кэш по двоичной картинке строки — на следующих кадрах
  читаются только изменившиеся строки;
* стрелочный прибор — круг (HoughCircles) с числами шкалы: числа — «чернила»
  циферблата без стрелки и рисок, Tesseract только цифрами; шкала — RANSAC
  «угол → значение»; стрелка — луч, сильнее всего отличающийся от циферблата;
* лампа — маленький круг, горит — насыщенный и яркий цвет; кнопка —
  прямоугольник с надписью, включена — насыщенная яркая заливка;
* шкала-полоса — дорожка дотягивается по цвету до фона (её рамка в Canny не
  видна), заливка — доля столбцов цвета левого края; резервуар — доля строк;
* числовое табло — число (разрядные группы «40 13» склеиваются; «Насос 1»,
  «CH4» — номер в подписи), единица после числа, подпись — слева в той же
  рамке, иначе сверху.

Качество — по истине генератора (`window.__truth`, только для стенда). На
шести станциях, которых распознаватель не видел при настройке (зёрна 101–106):

| прибор | найдено | подпись | значение / состояние |
|---|---|---|---|
| стрелочные приборы | 93 % | 100 % | 100 % (допуск 4 % шкалы) |
| шкалы-полосы | 94 % | 100 % | 100 % |
| кнопки | 88 % | 100 % | 100 % |
| лампы | 96 % | 95 % | 100 % |
| резервуары | 89 % | 75 % | 94 % |
| числовые табло | 93 % | 96 % | 93 % (точное совпадение текста) |

`python vm/zero_vision.py снимки/*.jpg` — оценка по снимкам с `*.json` истины
рядом. В дашборде не найденное показывается красным пунктиром, «Шаги OpenCV» —
как прочитан каждый прибор. Плейбуки для незнакомого щита — только по общему
виду: горит лампа с тревожной подписью → «Квитировать», если такая кнопка есть
(без проверки результата — смысл щита неизвестен); уровень у края шкалы.

## Демо

Кнопка «▶ Демо» (убирается крестиком, вернуть — в «Что можно нажимать?»)
проигрывает сценарий на выбранной системе с профилем; сцену готовит тестовый
канал стенда, дальше — только распознанное и HID:

* **авария → плейбук → ремонт**: изоляция падает до 4 кОм, защита отключает
  насос; система видит аварию, собирает плейбук и проходит ремонт → сброс
  защиты → пуск, подтверждая каждый шаг на экране;
* **окно поверх щита → самовосстановление**: панели под окном помечаются
  «не видно», Esc через HID, щит снова виден.

Панель справа внизу рассказывает шаги, дашборд сам переключает вкладки и
подсвечивает плейбук и текущий шаг. Проверено на всех трёх видах систем
(компоновки A и D первого щита, старый щит).

входят — их создаёт `regen_templates.py`.
