# Щит АСУ ТП нефтедобычи — стенд для компьютерного зрения

Щит скважины 1247 отрисован целиком на `<canvas>` 1920×1080 и служит
источником задачи: прочитать показания приборов из картинки, ничего не зная о
модели, которая эти показания породила. В репозитории три части.

| часть | что делает |
|---|---|
| [`neft-hmi-cv.html`](neft-hmi-cv.html) | сам щит: физика УЭЦН, мнемосхема, приборы, четыре компоновки, выгрузка датасета и эталонов |
| [`cv_templates/`](cv_templates/README.md) | эталонные образцы и скрипт сверки `match_templates.py` — проверка распознавания на контрольном наборе |
| [`live/`](live/README.md) | чтение щита с KVM-трансляции в реальном времени и вывод на локальный сайт |
| [`bridge/`](bridge/README.md) | двусторонний контур: эмулятор → программный «HDMI» (6 транспортов) → быстрое чтение → агрегация → управление щитом мышью и подсказки на его экран |
| [`tests/`](tests/) | автотесты: протокол, транспорты, агрегатор, управление, точность чтения на контрольных кадрах |
| [`neft-scada.html`](neft-scada.html) | первая версия щита, без разметки для CV — оставлена для сравнения |

## Быстрый старт

Нужны Python 3.10+ и Chrome или Edge (эмулятор запускает установленный браузер).

```bash
git clone https://github.com/maybeGILGAMESH/scada-cv-bridge.git
cd scada-cv-bridge
python -m venv .venv
.venv\Scripts\activate              # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

Весь контур — два терминала:

```bash
python bridge/emulator.py           # щит в Chrome, видеоканал :8780, обратный канал :8790
python bridge/receiver.py           # распознавание, агрегация, управление; сайт http://127.0.0.1:8771
```

Проверки:

```bash
pip install -r requirements-dev.txt
python -m pytest -q tests           # 26 тестов, ~15 с, браузер не нужен
python bridge/e2e_test.py           # сквозной прогон с Chrome: пуск, частота, штуцер, перестановки
python bridge/make_report.py        # отчёт по замерам → bridge/results/report.html
```

Тесты запускаются на GitHub при каждом push (`.github/workflows/ci.yml`:
Linux и Windows, Python 3.10 и 3.12). Сквозной прогон с браузером в CI не
входит: эталоны нарезаны в Chrome под Windows, а на Linux другие шрифты —
шапка щита растеризуется иначе, и сравнение с эталонами теряет смысл.

## Четыре компоновки — и зачем они

Первой версии можно было справедливо возразить: приборы стоят на известных
местах, поиск идёт в окрестности заранее записанной координаты, значит это не
распознавание, а чтение по координатам.

Возражение снято двумя изменениями.

**У щита появились компоновки.** Блоки переставляются целиком — мнемосхема,
манометры, индикаторы, щит сигнализации, пульт, столбчатые, тренды, журнал.
Размеры приборов и их отрисовка не меняются, меняются только координаты.
Переключение — списком «Компоновка щита» под панелью или клавишей <kbd>L</kbd>.

| A · базовая | B · зеркальная | C · приборы слева | D · полосы наоборот |
|---|---|---|---|
| мнемосхема слева, приборы в центре, сигнализация справа | колонки обеих полос в обратном порядке | манометры и индикаторы к левому краю | нижняя полоса поднята под шапку, верхняя опущена вниз |

**Скрипт сверки перестал верить координатам.** Перед чтением приборов он ищет
блоки щита в кадре — сопоставлением изображения, а не по записанным числам —
и только потом читает приборы там, где блок нашёлся.

Разница на одном кадре, эталоны нарезаны в компоновке A:

| кадр | чтение по якорям (`--anchored`) | поиск блоков (по умолчанию) |
|---|---:|---:|
| компоновка A | 100 % | 100 % |
| компоновка B | 49,3 % | 100 % |
| компоновка C | — | 100 % |
| компоновка D | 40,3 % | 100 % |

Контрольный набор из 14 режимов при этом не просел: **933 / 938 — 99,5 %**, те
же пять расхождений, что и раньше.

## Реальное время через KVM

Щит крутится на одном компьютере, распознаётся на другом: картинка уходит через
KVM на Pi Zero 2 и приходит видеопотоком.

```
ПК-1: neft-hmi-cv.html ──HDMI──▶ KVM (Pi Zero 2) ──сеть/USB──▶ ПК-2: live/run.py
                                                                     │
                                                        http://127.0.0.1:8770
```

```bash
pip install opencv-python numpy
python live/run.py --source http://pikvm.local/streamer/stream
```

Кадр с трансляции приходит не таким, каким его рисует браузер: он
отмасштабирован под разрешение захвата, сдвинут полями, пережат JPEG.
`matchTemplate` масштаба не прощает, поэтому кадр сначала возвращается к
1920×1080 — щит находится в кадре многомасштабным сопоставлением неизменного
куска шапки. На проверке с захватом 1280×800, где щит уложен в 1280×720 со
смещением и пережат JPEG качества 70, калибровка даёт масштаб 0,664 (точное
значение 1280/1920 = 0,667) и начало щита (0, 38) — ровно высоту чёрного поля;
показания при этом читаются верно, включая все шесть семисегментных
индикаторов.

Перестановку блоков живой конвейер замечает на следующем же кадре: поиск блоков
идёт не каждый кадр, но каждый кадр проверяется один блок по очереди, и при
сдвиге полный поиск запускается немедленно. Кадр читается за 1,7–2,7 с, первый —
за 8,8 с; манометры при этом в пределах 0,6 % шкалы, семисегментные индикаторы
читаются посимвольно верно во всех четырёх компоновках.

Сайт показывает не только числа, но и то, откуда они взялись: найденный масштаб
кадра, сдвиг каждого блока, балл привязки, время на кадр и сам кадр после
нормализации. Подробности — в [`live/README.md`](live/README.md).

## Порядок работы

1. Открыть `neft-hmi-cv.html` в Chrome или Edge.
2. Нажать **«Выгрузить эталоны»**, указав папку `cv_templates`. Список
   «контроль: все компоновки» выгрузит контрольные кадры во всех четырёх
   компоновках — это и есть проверка независимости от координат.
3. Прогнать сверку:

```bash
cd cv_templates && python match_templates.py
```

4. Для реального времени — поднять `live/run.py` на приёмной стороне.
